## Known Issues (NVIDIA + Wayland)

### Fullscreen/Resolution Settings Not Saving

**ProtonDB reports** (39 reports, Platinum rating):
- GE-Proton10-34 or Proton Experimental fixes the "limited to fixed window, no resolution change" bug
- Stock Proton 10 specifically has this issue on NVIDIA
- Alt+Enter twice (windowed→fullscreen) works as a band-aid for the 1/4-screen render bug
- Multiple RTX 3080/4070/4070 Ti users on CachyOS, Pop!_OS, EndeavourOS confirmed

**Workaround order:**
1. Set `PROTON_ENABLE_WAYLAND=0` in launch options
2. Use GE-Proton10-34 or newer (GE-Proton11-1 should work)
3. Alt+Enter twice if stuck in wrong resolution
4. Nuke prefix and regenerate as last resort

### Frame Limiter Broken

D2R stores limiter in Settings.json:
```json
"VSync": 0,
"Framerate Cap": 164,
"Framerate Target": 0
```

The game's frame limiter is CPU-side `Sleep()` based. Under VKD3D-Proton + Wayland + NVIDIA, it doesn't properly pace the Vulkan swapchain.

**Fix:** MangoHud `fps_limit` in `~/.config/MangoHud/MangoHud.conf` or Gamescope `-r 60`.

**MangoHud pitfalls to check:**
- `fps_limit=0` = **unlimited** — Goverlay sometimes writes this. Change to desired cap (`60`, `120`, `164`).
- `vulkan_present_mode=immediate` — **bypasses the fps_limit entirely**. Remove this line or set to `mailbox`.
- `vsync` valid range is -1 to 3. Values outside range are silently ignored.
- Env var override (takes priority over config file): `MANGOHUD_CONFIG="fps_limit=60,fps_limit_method=early,vulkan_present_mode=mailbox,no_display=1"`
- `fps_limit_method=early` gives better frame pacing than `late` under heavier workloads

### Graphics Settings Not Saving

- Check `Settings.json` permissions in the proton prefix
- Proton prefix ownership: `chown -R $USER:$USER ~/.local/share/Steam/steamapps/compatdata/2536520`
- Delete the entire `compatdata/2536520` folder to regenerate prefix

### DLAA Forcing

Requires DXVK-NVAPI with R610+ headers (see SKILL.md for building instructions). GE-Proton11-1 ships v0.9.2 (R595) — DRS DLAA settings are NOT recognized without an upgrade.

**Recommended — individual env vars (avoids comma parsing issues):**
```txt
DXVK_NVAPI_DRS_NGX_DLSS_SR_OVERRIDE=1 DXVK_NVAPI_DRS_NGX_DLAA_OVERRIDE=1 mangohud %command%
```
This creates two separate env vars that DXVK-NVAPI's `enrichwithenv()` picks up individually.

**Alternative — hex IDs in DRS_SETTINGS:**
```txt
DXVK_NVAPI_DRS_SETTINGS="0x10E41E01=1,0x10E41DF4=1" mangohud %command%
```
Where `0x10E41E01=1` = Enable DLSS SR override, `0x10E41DF4=1` = Enable DLAA mode.

⚠️ `PROTON_ENABLE_NVAPI=1` is NOT needed in GE-Proton11-1 — NVAPI is auto-enabled via `DXVK_ENABLE_NVAPI=1` unless explicitly disabled with `PROTON_DISABLE_NVAPI=1`.

**Why hex IDs instead of text keys:** The text key `ngx_dlss_sr_override_render_preset_selection=dlaa` maps to setting ID `0x10E41DF2` which is the RR (Ray Reconstruction) preset selection, NOT a DLAA setting. The correct DLAA setting is `NGX_DLAA_OVERRIDE` at ID `0x10E41DF4`, reachable only via hex ID or the individual env var `DXVK_NVAPI_DRS_NGX_DLAA_OVERRIDE=1` (if the DXVK-NVAPI build includes the lookup entry).

Set DLSS to Quality in-game (so DLSS pipeline stays active), then the override forces native resolution rendering.

## MangoHud Config

Current config: `~/.config/MangoHud/MangoHud.conf` (generated by Goverlay 1.7.5)

Key settings for D2R:
- `fps_limit=164` (165Hz display - 1) — **check this isn't 0** (0 = unlimited)
- `fps_limit_method=late` — change to `early` for smoother frame pacing
- `vulkan_present_mode=immediate` — **bypasses fps_limit**, remove or set to `mailbox`
- Add `no_display=1` to hide HUD
- Per-game override: `~/.config/MangoHud/diablo_ii_resurrected.conf`
- Env var override (takes priority): `MANGOHUD_CONFIG="fps_limit=60,no_display=1" mangohud %command%`
