# OpenCode SIGABRT Crash — ECC Plugin + Tools Loading Failure

## Session Context

**Date:** 2026-07-26
**System:** Manjaro Linux, KDE Wayland, NVIDIA RTX 5060 Ti
**Harness:** OpenCode Desktop v1.17.18 → v1.18.5
**Integration:** ECC (Everything Claude Code) v2.0.0

## Symptoms

- OpenCode desktop opens and the UI is functional
- Sending a prompt does nothing — no response, no error in the chat
- After ~2 minutes, the Node.js utility process crashes with SIGABRT
- Systemd records a coredump (~40MB)

## Root Cause

ECC's `opencode.json` had TWO problems:

**Problem 1 — Config paths:** The config points to TypeScript source instead of compiled JS:
```json
"plugin": ["./plugins"],          ← should be "./dist/plugins"
"skills": { "paths": ["../skills"] }  ← should be "./skills"
```

**Problem 2 — Tools directory loads TypeScript-in-disguise:** Even after fixing config paths, OpenCode auto-discovers `tools/` and loads `.js` files directly from it. ECC installs TypeScript source files in `tools/` that have `.js` extensions but contain `import/export` syntax (real JS is `require/module.exports`). The Node.js service aborts when these pseudo-JS files are loaded at tool resolution time.

## Install State

ECC was installed with:
- **Profile:** `minimal` → `full` (after reinstall)
- **Modules skipped:** `agents-core`, `rules-core` (`framework-language`, `machine-learning` on full)
- **Config generated by:** `platform-configs` module
- **Compiled JS:** Present in `dist/` (52 files)
- **Files total:** 283 (minimal) / 682 (full), all present

## Fix Applied

### Fix 1: Config Paths

Patched `~/.opencode/opencode.json`:

```patch
- "plugin": ["./plugins"]
+ "plugin": ["./dist/plugins"]
- "skills": { "paths": ["../skills"] }
+ "skills": { "paths": ["./skills"] }
```

Same fix applied to project-level config at `~/src/git/ECC/.opencode/opencode.json`.

### Fix 2: Tools Directory Symlinks

The config fix alone did NOT stop the crash. OpenCode discovers `tools/` at startup regardless of config paths. Create symlinks to the compiled JS outputs:

```bash
cd /opt/OpenCode
for f in tools/*.js; do
  ln -sf "../dist/$f" "$f"
done
ln -sf dist/plugins/index.js plugins/index.js
ln -sf dist/plugins/ecc-hooks.js plugins/ecc-hooks.js
```

This ensures the `.js` files in `tools/` actually load as compiled JavaScript.

## Key Insight

ECC's installer has TWO independent bugs that cause crashes:
1. Config generator points `plugin` to TS source instead of `dist/plugins` (always)
2. `tools/` contains TS-in-JS files that Node.js can't load (not fixed by config patch alone)

Both must be addressed. Reinstalling ECC resets both problems — fix must be re-applied after every reinstall.

## Detection Script

```bash
# Check if tools/ files are real JS or TS-in-disguise
head -3 /opt/OpenCode/tools/*.js | grep -E "import |export |from "
# Output means TS-in-JS (needs symlink fix):
#   import { something } from "module"

# Verify symlinks are in place
ls -la /opt/OpenCode/tools/*.js | head -5
# Should show: tools/foo.js -> ../dist/tools/foo.js
```
